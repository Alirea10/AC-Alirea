> 当前 ACT3 配置沿用攻血、生命流失和阻挡伤害，受伤时每次增加 1 层临时层数。三人档每名干员每场至多贡献 50 层，六人档解除上限。以下为旧凋亡效果的设计记录。

> 状态：已按当前赛季数据回写

## 当前实现概览

- 盟约 ID：kazdelShip
- 激活门槛：3 名；6 名不同干员解锁对凋亡损伤目标的伤害提升。
- 三人档新增：全场每次有凋亡损伤爆发时，每名【卡兹戴尔】干员各回复自身最大生命值的 20%；六人档继续保留，回复比例不随盟约层数成长。
- 成员数：10 名不同干员，20 条普通/精锐战斗棋子记录。
- 资料来源：bondInfoDict/kazdelShip.json、effectInfoDataDict/bondeffect_kazdel.json、effectBuffInfoDataDict/bondeffect_kazdel.json 和相关棋子记录。

## 参数与效果链

| 参数 | 当前值 | 说明 |
|---|---:|---|
| base_damage_scale / damage_scale_per_stack | 0.15 / 0.003 | 当前工作树中物理伤害附加凋亡损伤的比例及每层增量；沿用本轮开始前的数值 |
| base_ex_damage_scale / ex_damage_scale_per_stack | 1.25 / 0.01 | 六人效果中的伤害倍率及每层增量 |
| power_bond_char_cnt | 6 | 六名不同干员的效果门槛 |
| 爆发监听 Buff 的 hp_ratio | 0.2 | 每次凋亡爆发回复自身最大生命值的固定比例，不参与层数计算 |

主要模板为 buffTemplates/act1autochess_bond_eff_kazdel.json。

新增回复链：

1. 主模板保留现有【卡兹戴尔】成员筛选，通过后为自身创建派生的 `act1autochess_bond_eff_kazdel[watch]`，并明确以该干员作为 Buff 来源。
2. 监听器立即开始、每 0.1 秒向全场双方单位补充 `act1autochess_bond_eff_kazdel[burst]`；忽略距离、空地和隐匿等常规选敌限制，以覆盖后续入场单位。新入场单位需要等到下一次扫描后才获得监听，实际覆盖时序仍需战斗验证。
3. 爆发监听使用来源独立的唯一 Buff：同一来源不重复叠加，不同卡兹戴尔干员互不覆盖。`ON_EP_BREAK_START` 仅通过 `DARK` 类型过滤，其他元素损伤爆发不触发回复，也不限制凋亡损伤的施加者。
4. `HealViaMaxHpRatio` 沿用原版 `blaze2_t_1` 的来源回血组合：向 `BUFF_SOURCE` 回复生命，`_getMaxHpFromTarget=false`，按卡兹戴尔来源的最大生命值计算。`hp_ratio=0.2` 固定写在监听 Buff，忽略常规不可治疗限制并跳过治疗修正事件；不向发生爆发的单位或其他非卡兹戴尔干员分摊回复。
5. 两层 Buff 均随父 Buff 结束清理；干员移除或盟约 Buff 结束后的清理时序需要实际战斗核对。

编辑器现有 `BuffTemplate`、事件与节点编辑、目录保存以及普通/PE JSON 导出可承载此链，无需增加客户端或服务端能力。原版参考为 `blaze2_t_1` 的元素爆发与来源回血节点，以及 `enemy_dyshhj_s_withdraw[global]` 的全场双方选取节点；资料提交为 `1bab58e6d70b7b12db9c0afffadd75b07b9307a8`。
