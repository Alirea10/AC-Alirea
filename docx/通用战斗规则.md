# 通用战斗规则

客户端通过现有 `AutoChessTriggerGarrisonAbility` 入口执行六类参数化规则。角色、盟约和模板由赛季 JSON 指定，不需要新增客户端角色分支。需要配套支持 `battle-rule-runtime` 的客户端；旧 `sami_event` / `sami_trait` 配置不再兼容。

## 配置位置与身份

- 开战规则放在来源盟约的 `effectBuffInfoDataDict[effectId]`，其 `source_bond` 必须指向使用该效果的盟约。该盟约激活后，只登记实际属于该盟约的在场角色。
- 特质放在 `garrisonDataDict`，由角色的 `garrisonIds` 挂载。一个角色可挂载多条不同规则。
- Blackboard 仍为 `{ "key": "参数名", "value": 数字, "valueStr": 字符串或null }`。字符串填 `valueStr`，数字填 `value` 并将 `valueStr` 设为 `null`。以下表格和简写对象均指 Blackboard 的键值。
- `key` 指定事件转发模板，`rule_event=register` 登记规则，`rule_event=skill` 只转发技能事件。参数取自已成功安装的赛季配置，不从临时修改的原生 Blackboard 重新读取。
- `rule_kind` 指定能力；`rule_group` 指定开战结果所属结算组；`rule_id` 指定规则身份。实例内的 `(rule_group, rule_id)` 必须唯一，普通／精锐可使用同一身份但不同参数。
- `skill_roll` 省略 `rule_group` 即可独立工作。其他能力必须关联一个有效的开战组；一个组只能有一个开战配置。组间独立等待、按组名排序执行，玩家按索引排序。

通用事件模板：`act1autochess_rule_register` 在 `ON_BUFF_START` 登记；`act1autochess_rule_skill_event` 在 `ON_SKILL_CAST_SUCCEED` 转发技能事件。技能特质需同时挂载登记与技能事件两条 garrison，二者的 `rule_id`、`rule_group` 一致。独立技能特质的两条配置均省略 `rule_group`。

## 能力参数

所有随机整数区间都包含两端。数值必须有限，次数与随机界限必须为合法整数。`priority` 默认 `0`，越大优先，同优先级按实例 ID、规则 ID 排序。

| rule_kind | 参数与行为 |
|---|---|
| `opening_roll` | `source_bond`、`roll_min`、`roll_max`、`target_bonds` 必填；`min_members` 默认 1；`count_mode` 默认 `character`（不同角色），可改 `instance`（实例数）；`min_per_member`、`max_per_member` 默认 0。范围为 `[roll_min + min_per_member×人数, roll_max + max_per_member×人数]`。每个实例独立抽取一次；同组该实例的所有目标盟约共用结果。 |
| `extreme_draw` | `draw_count` 为 1～1000，修改自身的开战抽取次数，取绝对值最大的一次，相同时取正值。同实例多个此类规则取优先级最高者。 |
| `result_offset` | `target=self/front`；`chance_wins`、`chance_sides` 定义成功概率（例如 1/2）；成功加 `gain`，失败减 `loss`。目标必须有本组开战结果。同一规则 ID 对同目标只修正一次，由 `priority` 选胜出者；不同规则 ID 可依次修正。 |
| `count_buff` | 用 `comparison` 与 `threshold` 筛选本组最终结果；`count_mode` 默认 `character`；统计数经 `count_cap` 限制后乘 `hp_ratio`，再乘受益者最大生命值，写入 Buff 的 `buff_value_key`；`target=self/group` 指自身或所有本组抽取者。同规则 ID 的 group 效果仅取最高优先级，self 效果按受益者分别选择。比例为 0 时不发 Buff。 |
| `threshold_buff` | 自身最终抽取结果满足 `comparison` 与 `threshold` 时施加 Buff。`restore_on_recreate` 默认 0，设为 1 则角色重建后恢复已获得的效果，仅支持未配置 `duration` 的永久 Buff。 |
| `skill_roll` | 每 `skill_interval` 次技能成功触发一次，最多 `max_triggers` 次；使用 `roll_min`、`roll_max`、`target_bonds`。计数归属于本场战斗的角色实例和规则；关联组时等待该组结算，没有关联组时独立运行。 |

`comparison` 可选 `lt/le/eq/ge/gt`。比较对象是押注修正后的抽取结果，不是经过盟约层数上下限截断后的实际增量。

`target_bonds=self` 表示角色当前所属的所有已激活盟约；否则填写逗号分隔的盟约 ID。指定目标只影响其中已激活的盟约，去重后写入。负层数在 0 截断，其他原生上限仍有效；客户端上报实际读回的变化量。

两类 Buff 规则都支持：

| 参数 | 说明 |
|---|---|
| `buff_template` | 必填，赛季 `buffTemplates` 中的模板键。 |
| `buff_values` | JSON 对象字符串，默认 `"{}"`；值仅支持数字或字符串，例如 `"{\"damage_scale\":1.4}"`。 |
| `duration` | 可选，正数秒；省略表示本场永久。 |

Buff 的实例键按角色、结算组、规则 ID 生成，同模板被不同规则使用时不会共享同一 Buff 身份。重建只恢复已获得且声明可恢复的奖励；不会重新抽取或重新发放统计护盾。

## 非萨米示例：独立技能特质

下面两条 garrison 可挂到任意角色，不依赖开战盟约。每两次成功施放技能，使自身已激活盟约共用一次 1～3 层抽取，最多三次。其余 `effectType=GAIN_BUFF`、`eventType=IN_BATTLE`、`battleRuneKey=env_gbuff_new_with_verify` 等字段沿用普通战斗特质格式。

登记条目的 `blackboard`：

```json
[
  { "key": "key", "value": 0, "valueStr": "act1autochess_rule_register" },
  { "key": "rule_event", "value": 0, "valueStr": "register" },
  { "key": "rule_id", "value": 0, "valueStr": "skill_bonus" },
  { "key": "rule_kind", "value": 0, "valueStr": "skill_roll" },
  { "key": "skill_interval", "value": 2, "valueStr": null },
  { "key": "max_triggers", "value": 3, "valueStr": null },
  { "key": "roll_min", "value": 1, "valueStr": null },
  { "key": "roll_max", "value": 3, "valueStr": null },
  { "key": "target_bonds", "value": 0, "valueStr": "self" }
]
```

技能事件条目的 `blackboard`：

```json
[
  { "key": "key", "value": 0, "valueStr": "act1autochess_rule_skill_event" },
  { "key": "rule_event", "value": 0, "valueStr": "skill" },
  { "key": "rule_id", "value": 0, "valueStr": "skill_bonus" }
]
```

## 非萨米示例：盟约开战规则与配套特质

在自定义盟约 `exampleShip` 的效果条目中使用下列键值（按前述 Blackboard 格式展开），并在赛季中正常声明该盟约、效果及激活条件：

```json
{
  "key": "act1autochess_rule_register",
  "rule_event": "register",
  "rule_id": "opening",
  "rule_kind": "opening_roll",
  "rule_group": "example_opening",
  "source_bond": "exampleShip",
  "min_members": 2,
  "count_mode": "character",
  "roll_min": -5,
  "roll_max": 5,
  "max_per_member": 2,
  "target_bonds": "self"
}
```

某角色通过另一条 garrison 挂载以下参数，即可获得该组的三次极值抽取；其余角色和萨米不会受影响：

```json
{
  "key": "act1autochess_rule_register",
  "rule_event": "register",
  "rule_id": "extreme",
  "rule_kind": "extreme_draw",
  "rule_group": "example_opening",
  "draw_count": 3
}
```

## 萨米迁移与验证

主盟约使用 `sami_opening` 组；远山、雪绒、柏喙、凛视、提丰分别使用极值抽取、统计护盾、技能抽取、身前结果修正、结果奖励。普通／精锐参数保留。提丰按层数增长攻击力仍用原生 `act1autochess_rule_bond_growth` 模板，`bond_id`、`divide_num`、`atk_per_stack` 继续可配置。

**已知说明差异：**旧配置排他上界为 16，旧客户端减 1 后得到 15。本次迁移使用包含上界 15，实际为 `-30～(15+5×不同角色数)`，两人为 `-30～25`。盟约说明仍写 `20+5×人数`，按本次约定只记录差异，不改玩法或既有说明。

顺序保持为：等待本组登记 → 按实例抽取 → 结果修正 → 统计／奖励判定 → 写入全部层数 → 按实例施加 Buff → 重放提前到达的关联技能事件。未激活的开战盟约不会抽签，但已挂载的技能规则仍可在空结算完成后工作。

无效声明在赛季安装时输出 `battle-rule-config-error` 并停用对应规则，不进入等待名单。运行时诊断包括 `battle-rule-roster`、`battle-rule-waiting`、`battle-rule-opening`、`battle-rule-direct`、`battle-rule-write-skipped`、`battle-rule-error`。原生登记失败只停用对应实例规则；组计算失败隔离到该组。

本地已用固定随机序列对照迁移前规则；原生实战还需要匹配的新客户端和赛季完成一局，核对技能触发、Buff 表现、实际层数上报和战后保留。不要将纯规则测试通过视为已经完成实战验收。
